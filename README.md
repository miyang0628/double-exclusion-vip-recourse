# Double Exclusion: Auditing Intersectional Fairness in VIP Approval and Post-Rejection Recourse

**A reproducibility repository for a manuscript under double-blind review.**

> **Anonymized submission.** This repository accompanies a manuscript submitted to an anonymized venue. All author-identifying information has been removed for review. A de-anonymized version with full attribution will be released upon acceptance.

## Overview

Conventional fairness audits of financial AI stop at the decision itself — *who is approved and who is rejected*. This project asks a second question that the literature has largely left open: **when a member is rejected, is the recourse advice they receive actually actionable?**

Using a large public synthetic dataset of card-usage behavior, we audit an opportunity-allocation model (premium / VIP-tier membership) along two axes and combine them into a single index:

1. **Axis 1 — Approval.** A **Conditional Disparity Ratio (CDR)** between an advantaged and a disadvantaged intersectional profile.
2. **Axis 2 — Recourse.** Counterfactual recourse is generated under three governance scenarios, and judged **reliable** only if it changes no immutable feature, keeps every actionable change within a ±20% action horizon, and leaves the issuer-controlled (non-controllable) features unchanged.
3. **Double Exclusion Index (DEI).** The two axes are combined as an *exact joint probability* (chain rule) of being both rejected and left without any reliable recourse.

The disadvantaged group (older women with short credit tenure) is far less likely to be approved and, once rejected, receives virtually no feasible recourse; the recourse gap exceeds the approval gap and falls on the same members.

## How to run

```bash
python -m venv venv && source venv/bin/activate      # or conda
pip install -r requirements.txt
```

Then run the notebooks in order (`01 → 02 → 03 → 04 → 05`). Notebook 01 is the expensive stage and caches its artifacts to `results/cache/`, so notebooks 03–05 can be re-run independently. The two DiCE-based robustness checks in notebook 04 (action-horizon and search-budget sweeps) store their seed-fixed values by default; set `RUN_DICE = True` at the top of that notebook to regenerate them.

## Reproducibility notes

- **Fixed seeds throughout** (`random_state = 42`; bootstrap seed fixed).
- **One governance partition** of twelve features (5 immutable + 6 actionable + 1 non-controllable) drives *both* the model and the recourse constraints, so an infeasible recommendation is defined once, before any recourse is generated.
- **Categorical-aware generation.** Nominal features (gender, region, life stage) are declared categorical to the counterfactual generator, so the search ranges over valid feature levels rather than fractional codes; the main and robustness analyses use one identical configuration.
- **Measured, not extrapolated.** The headline disadvantaged reliability bound is computed over the entire rejected pool, not inferred from a small sample.
- **Figures.** Figures 3–6 are generated by notebook 05 with seaborn in grayscale (print-safe), saved as PNG (600 dpi) and PDF, with captions omitted (they live in the manuscript). Figures 1–2 are the concept and feature-governance schematics, prepared separately.

## Data access

The analysis uses a public synthetic financial (card-usage) dataset. The raw files are **not redistributed** here. To reproduce:

1. Obtain the three required source tables — member information, credit information, and approval/sales — from the original public provider.
2. Place the CSV files under `data/` (any subfolder structure is fine; notebook 01 locates each table by its column header signature).
3. Run the notebooks in order.

> **Note.** Only the member / credit / approval tables are needed. External credit-bureau tables are intentionally not used, to keep the audit in a limited-information setting.
